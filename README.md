# Freeter

단기 아르바이트·교대근무자를 위한 웹사이트입니다. 로그인 없이 브라우저에서 사용하고, 선택적으로 Google 로그인과 Supabase 계정 저장·기기 간 동기화를 이용합니다. 프런트엔드는 GitHub Pages에 정적으로 배포하며 방문자는 설치나 빌드가 필요하지 않습니다.

공개 사이트: https://kawaiidoro.github.io/freeter/

## Freeter 브랜드와 위젯 대시보드

- 속도감을 준 영문 **FREETER**·한글 **프리터** 로고를 복원했습니다. 프로필·도구 아이콘·최근 기록·업무 메모·월별 기록을 둥근 위젯으로 배치하며, 프로필 카드의 슬로건은 **저는 단기알바입니다.** 입니다.
- 배경 `#121212`, 차콜 카드 `#181818`·`#222222`, 액션 `#1ED760`의 색상은 유지합니다. 라이트 모드는 `#F7F7F7`·흰색 카드와 짙은 글자를 사용합니다. `freeter:theme`에 기기별 테마를 저장합니다.
- 메뉴 순서는 대시보드 → 알바 지원 → 업무 메모장 → 교대 근무표 → 급여 계산기 → 나의 알바 기록 → 수입 통계입니다. 모바일에서도 동일한 순서로 바로 이동합니다.
- **알바 지원:** 지원한 공고를 제목만 있는 게시판으로 모아 두고, 제목을 눌러 내용·링크를 읽고 수정·삭제합니다. 제목 검색과 10개씩 페이지 구분을 제공합니다. 단기 알바 경력과 문자 지원 양식은 입력 즉시 자동 저장하며 복사할 수 있습니다. 기본 문자 양식은 `행사명/이름/나이/거주지/경력사항`입니다.
- 지원 자료는 기존 근무·급여·메모와 함께 JSON 백업·복원에 포함됩니다. 로그인 상태에서는 기존 계정 공간에도 동기화하며, 서로 다른 공고는 항목별로 병합하고 같은 공고나 같은 경력을 동시 수정하면 충돌을 확인합니다. 공고 링크는 HTTP(S)만 허용하고 본문은 HTML로 실행하지 않습니다.
- 기존 백업에는 지원 항목의 기본값을 보완하며, 저장 키 `dangi-alba:data`와 형식 버전 3은 그대로 유지합니다.
- `assets/{applications,notes,schedule,calculator,records,stats,settings,guide}-icon.png`는 같은 그린·블랙 입체 스타일의 도구 일러스트 8종입니다. `assets/freeter-wordmark.png`, `freeter-logo.svg`, `freeter-share.png`에도 복원한 레이싱 로고를 적용합니다.
- 모바일 근무표는 전체 근무자를 화면 안에 표시하며, 생성 후 결과를 먼저 보여줍니다. 근무자 칸을 눌러 해당 구간 휴식자를 바꿀 수 있습니다. 테마·기존 기록·PNG 저장 등 나머지 도구는 유지합니다.
- 하단은 사용법·개인정보·백업 링크와 저작권만 남기고, 상단 정보는 날씨 → 날짜 → 분 단위 시간 순서입니다.

## 추가된 근무 관리 기능

- **여러 날 급여 미리보기:** 총 근무일 수(1~366일), 1일 실근무시간, 전체 실근무시간, 일급과 전체 예상 수령액을 `₩`로 표시합니다. 근무시간·휴게·급여·세금 입력은 1일 기준이며, 기록 저장은 선택한 날짜의 하루치만 저장합니다. 기존 기록과 백업도 그대로 읽습니다.

- **지급 완료로 변경:** 기록의 버튼을 누르고 실제 입금일·남은 금액을 확인해 저장합니다. 기존 분할 입금은 보존하고 입금 내역을 추가하므로 수입 통계에도 반영됩니다. 실제 입금이 없는 상태에서 상태만 완료로 바꾸지 않습니다.
- **세금 유형:** 공제 안 함 / 일용근로소득 / 프리랜서 사업소득(통상 3.3%)을 선택합니다. 기본급·추가 지급·비과세·세금·기타 공제를 구분하고 예상 수령액을 계산합니다.
- **공평 배분·점심 복귀:** 새 근무표는 공평 배분을 기본으로 하며, 휴식과 점심 모두 기본 A→B→C 순서를 유지합니다. 점심 때문에 휴식 순서를 자동으로 교환하지 않습니다. 공평 배분(v4)은 설정한 교대 간격으로 모두 한 바퀴씩 쉰 뒤 마지막 남은 시간을 균등하게 나눕니다. 예: 60분이 남으면 20분씩, 30분이면 10분씩. 나누어떨어지지 않아도 근무시간 차이는 최대 1분입니다. v1·v2·v3 저장 근무표는 원래 규칙으로 검증합니다. 기존 구간과 수동 배정은 그대로 보존하며, 안내 후 다시 생성할 때 새 규칙을 적용합니다.
- **휴식 조정:** 결과 표의 ‘휴식 조정’에서 시간 구간(한 바퀴)별 1인 휴식 길이를 바꾸거나, 정확한 시작·종료 시각으로 휴식 없는 시간대를 추가합니다. 순환 간격 변경은 모든 사람에게 같은 길이로 적용하고 마지막 자투리만 균등 배분합니다. 휴식 없는 구간에는 모두 근무하며 점심은 유지합니다. 겹친 제외 시간은 한 번만 계산하고, 취소·오류·다른 기기의 최신 편집은 기존 표를 덮어쓰지 않습니다. 조정 설정과 전원 근무 구간은 계정·새로고침·JSON·CSV·PNG에도 보존합니다.
- **PNG 저장:** 웹페이지의 실제 결과 카드를 DOM 이미지로 저장해 현재 테마·근무/휴식/점심 배지·이름·합계를 유지합니다. 긴 표는 캔버스 한도 내에서 여러 장으로 나눕니다. `html-to-image` 1.11.13(MIT)을 고정하고 자체 호스팅합니다.
- **2인 맞교대:** 일반 구간 1명 근무·1명 휴식. 기존 3인 밀어내기는 2명 근무·1명 휴식입니다.
- **점심 방식:** 모두 함께, 1명씩 순서대로, 2명 먼저·1명 나중을 선택합니다. 2명이 함께 식사하는 구간은 1명만 근무하며 별도 색으로 정확하게 표시합니다. 2인 맞교대에서는 함께 식사 또는 1명씩 식사를 제공합니다. 식사 시작·1인 식사시간·첫 식사자를 지정할 수 있습니다.
- **이름 입력:** 기본 이름을 실제 값으로 채우지 않고 빈 입력 안내로 표시합니다. 클릭하면 안내가 숨겨지며 이미 입력한 실제 이름은 보존합니다.
- **도우미 위치:** 구석의 움직이는 곰씨·말풍선·숨김/복원 버튼을 제거했습니다. 날씨는 모든 페이지 상단의 날씨 버튼에서 엽니다.
- **상단 정보:** 날씨 → 날짜 → 시간 순서로 표시합니다. 시계는 기기의 현지 시각을 분 단위(`HH:mm`)로 표시하며 아이콘·초 표시 전환 기능은 없습니다. 기존 초 표시 설정도 읽지 않습니다. 날짜·시각 갱신은 메모와 커서를 바꾸지 않습니다. 모바일에서는 상단 두 번째 줄에 배치합니다.
- **곰씨 날씨:** 손그림 일러스트와 함께 습도·오늘 최대 자외선·일출·일몰·PM10·PM2.5 및 국내 농도 등급도 표시합니다. 대기질은 Open-Meteo의 CAMS 예측값이며 기준 시각과 출처를 표시합니다.  상단 날씨 버튼을 누르면 선택 지역의 현재 기온·체감온도·오늘 최고/최저를 확인합니다. 기본 지역은 서울이며 지역 변경·내 위치 선택을 지원합니다. 위치 권한은 내 위치 버튼에서만 요청하고 좌표는 소수점 둘째 자리만 Open-Meteo에 전송합니다. 위치는 계정이나 localStorage에 저장하지 않습니다. 날씨 오류·오프라인에서는 재시도와 지역 선택을 제공합니다. 움직임 줄이기 설정을 따릅니다.
- **업무 메모장:** 한글 IME 조합이 시작되는 즉시 입력 안내를 숨기며, 비우면 안내를 다시 표시합니다.  굵게·14~32px 크기·밑줄·글자색·형광펜을 선택한 글자에 적용합니다. 항상 편집할 수 있으며 입력 즉시 자동 저장합니다. 저장 버튼과 JSON 백업에도 서식이 유지됩니다. TXT·복사는 일반 텍스트를 내보냅니다. HTML 내보내기 취약점을 수정한 Quill 2.0.3을 `vendor/`에서 자체 호스팅하며 BSD 라이선스를 동봉합니다. [보안 변경](docs/SECURITY.md)을 참고하세요. 임의 HTML은 저장하지 않고 문자열과 검증한 서식 속성만 저장합니다.
- **업데이트 내역:** 홈·상단 업데이트 아이콘·사용 가이드의 버튼을 누르면 새 근무 관리 도구 안내와 곰씨 캐릭터를 한 창에 표시합니다. 기본 화면에서는 내용이 접혀 있습니다.
- **작은 계산기:** 급여 계산 화면 옆에서 사칙연산·괄호·음수·소수·키보드 Enter를 지원합니다. 문자열을 코드로 실행하지 않습니다.

### Google 계정과 동기화

계정 아이콘 또는 데이터 · 설정에서 Google로 로그인합니다. Supabase Auth·계정별 DB·RLS·설정 스크립트와 Google 제공자 연결 절차는 [서버 설정 지침](docs/SUPABASE.md)에 있습니다. 공개 URL·Publishable key는 `cloud-config.json`에, 관리자 토큰과 Google client secret은 환경 설정 또는 Supabase 대시보드에만 보관합니다.

로그인 전 기록은 자동 전송하지 않습니다. 로그인 후 **브라우저 기록 가져오기**에서 백업·확인 후 계정으로 옮길 수 있습니다. 지정된 Google 계정만 로그인하며, 같은 계정의 기기에서 기록·입금·근무표·메모와 서식을 약 10초 간격으로 동기화합니다. 서버 오류 시 자동 재시도 간격은 최대 60초까지 늘어납니다. 독립된 기록을 합치고 같은 항목의 충돌은 백업 후 선택합니다. 전체 교체·삭제는 오래된 기기의 자동 복원을 막습니다. 로그아웃은 서버 응답을 기다리지 않고 로그인 정보를 지웁니다. 확인된 계정 사본은 삭제하고, 미전송 기록은 UID별 기기 저장소에 보관하여 같은 계정으로 다시 로그인할 때 전송합니다. 서버의 소유자 전용 RLS와 두 Auth Hook 설정도 필요합니다. [PGRST003 장애 원인·복구 및 계정 제한 설치](docs/SYNC-RECOVERY.md)를 참고하세요.

이전 연결 코드 교환과 WebRTC 기능은 사용하지 않습니다. 근무표 텍스트 공유·PNG·CSV와 JSON 백업·복원은 유지합니다.

### 세금 계산 기준

일용근로소득은 **기록 1건 = 1일분을 따로 지급**받는 예상 원천징수 기준입니다.

```text
과세급여 = 세전 기본급 + 추가 지급액 − 확인된 비과세 금액
일용 소득세 = max(과세급여 − 150,000원, 0) × 6% × (1 − 55%)
일용 소득세 1,000원 미만은 소액부징수로 0원
프리랜서 사업소득 소득세 = 과세 지급액 × 3%
지방소득세 = 소득세 × 10%
소득세·지방소득세 각각 10원 미만 절사
예상 수령액 = 세전 기본급 + 추가 지급액 − 소득세 − 지방소득세 − 기타 공제액
```

예: 일용 200,000원 → 소득세 1,350원 + 지방소득세 130원 → **198,520원**. 프리랜서 200,000원 → 합계 6,600원 → **193,400원**.

여러 날의 일용 급여를 한 번에 지급받으면 소액부징수 판단이 달라질 수 있습니다. 법상 일용근로 요건·사업소득 여부·비과세는 지급처와 확인하세요. 4대보험·최종 정산세액과 법정 수당은 별도입니다. 자동 계산 세금을 기타 공제액에 중복 입력하지 마세요. 추정값이며 실제 지급 명세서와 다를 수 있습니다.

법령 참고: [소득세법 제47조](https://www.law.go.kr/법령/소득세법/제47조), [제59조](https://www.law.go.kr/법령/소득세법/제59조), [제86조](https://www.law.go.kr/법령/소득세법/제86조), [제129조](https://www.law.go.kr/법령/소득세법/제129조), [국고금 관리법 제47조](https://www.law.go.kr/법령/국고금관리법/제47조), [국세청](https://www.nts.go.kr/nts/main.do). 해당 원문 사이트는 이번 클라우드에서 503·접속 오류가 발생해 최신 개정 여부를 독립적으로 확인하지 못했습니다. 화면은 위에 명시한 산식을 적용합니다.

## 실행하기

저장소 폴더에서 Python 3의 정적 파일 서버를 실행합니다.

```sh
cd /workspace/dangi-alba
python3 -m http.server 4173 --bind 0.0.0.0
```

개인 컴퓨터에서는 터미널이 안내하는 포트로 브라우저에서 접속하세요. 클라우드 작업에서는 로컬 HTTP 요청으로 확인하고, 서비스 프로세스는 새 작업에서 다시 시작합니다. 일반 정적 호스팅으로도 그대로 실행됩니다. 파일 미리보기보다 GitHub Pages 등 일반 웹주소 사용을 권장합니다. 제한된 미리보기에서는 계산과 근무표를 사용할 수 있지만 브라우저 저장·설치·공유가 제한될 수 있습니다.

실행용 `site.js`에는 메모 편집기와 Supabase 공식 SDK·계정 코드를 하나로 포함합니다. 화면과 스타일에는 같은 릴리스 버전이 붙으므로 새 HTML에 예전 스크립트가 섞이는 문제를 방지합니다. 일반 스크립트이므로 미리보기의 모듈 CORS 제한에도 첫 화면을 열 수 있습니다. 저장소에 접근할 수 없으면 기록을 지우거나 시작을 중단하는 대신 경고하고 메모리에서 동작합니다. History API가 제한되면 해시 이동으로 전환합니다.

## 제공하는 기능

### 밀어내기 근무표

- 근무자 세 명의 이름, 전체 일정, 점심시간, 교대 간격, 첫 휴식자를 설정합니다.
- 모든 근무 구간은 2명 근무·1명 휴식입니다. 점심에는 모두 쉽니다.
- 점심시간에는 교대 타이머를 멈추고, 점심 후 같은 휴식자가 남은 교대시간과 A→B→C 순서를 이어갑니다.
- 마지막 구간은 종료시간에 맞춰 줄어듭니다. 자정을 넘는 일정도 지원합니다.
- `공평하게 배분`은 총 휴식시간을 분 단위로 최대 1분 차이로 나눕니다. 설정한 간격으로 완전한 순환을 먼저 배정하고 마지막 남은 시간만 같은 길이로 나눕니다.
- 생성 후 휴식자를 수동으로 바꿀 수 있습니다. 개인별 총근무·휴식·점심시간과 실제 근무시간 차이를 표시합니다.
- 이름은 입력 즉시 결과에 반영됩니다. 시간·규칙은 재생성해야 반영되며 변경 알림이 표시됩니다.
- PNG 이미지, 한글 CSV, 텍스트 복사와 기기 공유 메뉴를 지원합니다. 공유 메뉴 지원은 브라우저에 따라 다릅니다. 매우 긴 근무표의 PNG는 이미지 크기 한도에 맞춰 여러 장으로 나누어 다운로드합니다.
- 급여 계산은 포함하지 않습니다.

예: 10:00–19:00, 점심 10:00–11:00, 60분 교대, 공평 배분 → A·B·C 모두 5시간 20분 근무, 식사 외 휴식 2시간 40분씩.

### 급여 계산기

- 시급제 기본급 = `(전체 근무 분 − 무급 휴게 분) ÷ 60 × 시급`, 원 단위 반올림.
- 일급제 기본급 = 입력한 계약 일급. 근무시간을 다시 곱하지 않습니다.
- 예상액 = 기본급 + 추가 지급액 − 직접 입력한 공제액.
- 분 단위·자정 넘김을 지원합니다. 0시간과 24시간이 모호한 동일 출퇴근 시각, 근무시간 이상의 휴게시간, 음수 예상액은 거부합니다.
- 3.3%는 기본 공제하지 않습니다. 주휴·야간·연장 등 법정 수당은 자동 판단하지 않습니다.
- 근무일·근무지를 입력하고 버튼 한 번으로 기록장에 저장합니다. 같은 입력의 즉시 중복 클릭을 방지합니다.

### 나의 알바 기록

- 근무일·근무지·업무·출퇴근·휴게·시급/일급·추가/공제·지급 예정일·메모를 관리합니다.
- 날짜별로 여러 건의 실제 입금을 추가할 수 있어 일부 지급을 지원합니다.
- 지급 상태는 자동 계산합니다: 총입금 ≥ 예상액이면 지급 완료, 0원 초과 일부 입금이면 일부 지급, 입금이 없고 예정일이 지났으면 미지급, 나머지는 지급 예정입니다. 예상액 0원은 지급 완료입니다.
- 수정, 확인 후 삭제, 근무 월·근무지·지급 상태 필터, 검색, 날짜 정렬 및 근무지별 수령액 합계를 제공합니다.
- CSV 버튼은 현재 조회된 기록을 내보냅니다. 데이터 · 설정에서는 전체 기록을 CSV로 내보냅니다.

### 수입 통계

- 근무한 날짜를 기준으로 일수(같은 날짜 중복 제외), 유급시간, 예상 급여를 집계합니다.
- 실제 현금 수입은 **입금 날짜가 속한 달**에 집계합니다. 전월 근무 급여를 다음 달 받더라도 혼동하지 않습니다.
- 미수령은 선택한 달 근무의 `max(예상액 − 해당 기록의 모든 입금액, 0)` 합계입니다. 초과 입금이 다른 기록의 미수령을 상쇄하지 않습니다. 현재 남은 금액이며 과거 월말 잔액의 재현은 아닙니다.
- 최근 6개월 막대그래프, 접근 가능한 데이터 표와 근무지별 내역을 제공합니다.

## 브라우저 저장과 백업

- 고정 키: `dangi-alba:data`, JSON 형식 버전: `3`. 기존 버전 1·2 데이터·백업을 읽어 근무·입금·수동 배정을 보존하고 새 항목을 기본값으로 보완합니다. 기존 기록은 세금 유형 `공제 안 함`으로 보존합니다.
- 이름, 마지막 근무표 설정과 결과, 근무지 목록, 근무·입금 기록, 계산기·세금 입력, 업무 메모, 테마를 저장합니다. 기록 편집 폼은 **기록 저장**을 눌러 반영합니다.
- 로그인 전 기록은 브라우저에만 보관하고, 로그인 후 기록은 Supabase의 현재 계정에 저장합니다. 계정 캐시는 프로젝트·사용자 ID별로 분리하며 게스트 키를 덮어쓰지 않습니다. 개인정보 안내를 확인하세요.
- 시크릿 모드 종료·브라우저 데이터 삭제·브라우저 정책에 따라 기록이 사라질 수 있습니다. 공용 PC의 같은 브라우저 사용자에게는 기록이 보일 수 있습니다.
- 정적 호스팅 제공자는 사이트 접속에 필요한 접속 정보를 처리할 수 있습니다. 현재 사이트에는 광고·분석·추적 스크립트가 없습니다.

**백업:** 데이터 · 설정 → 전체 기록 JSON 다운로드. 파일은 암호화하지 않으므로 안전하게 보관하세요.

**복원:** JSON 파일 불러오기 → 구조 검증 → 현재 데이터 교체 확인. 복원은 병합이 아니라 전체 교체입니다. 기존 기록도 먼저 백업하세요. 잘못된 파일은 거부하고 기존 데이터를 보존합니다. 지원하지 않는 미래 버전도 임의로 덮어쓰지 않습니다.

**CSV:** UTF-8 BOM을 포함하여 한글을 보존합니다. 스프레드시트 수식으로 해석될 수 있는 입력의 앞에는 작은따옴표를 붙입니다. CSV는 열람용이며 복원용은 JSON입니다.

**삭제:** 로그인 전에는 이 서비스의 브라우저 자료를 삭제하고, 로그인 후에는 현재 계정의 기록을 비워 다른 기기에 반영합니다. 삭제 전에 범위를 알리고 확인합니다. 이미 다운로드·공유한 파일은 직접 삭제하세요.

저장 용량 초과나 손상 데이터가 발견되면 화면에 경고합니다. 손상된 원본을 자동 삭제하지 않습니다. 새로고침 전에 JSON 또는 기존 저장 원본을 백업하세요. 여러 탭을 동시에 열 경우 다른 탭의 변경을 반영하며 저장하지 않은 편집은 사라질 수 있습니다. 같은 도메인의 정적 사이트들은 브라우저 저장 영역을 공유하므로 독립 운영이 필요하면 별도 도메인과 저장 키를 사용하세요.

## GitHub Pages 배포

1. 이 폴더의 파일을 `kawaiidoro/freeter` 저장소의 `main` 브랜치 루트에 업로드하고 커밋합니다. ZIP을 사용할 때는 **압축을 풀고 그 안의 파일**을 올리세요. `.git` 폴더는 업로드하지 않습니다.
2. 최초 1회 GitHub 저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다. 이 설정은 저장소 관리자 권한이 필요하며 일반 Actions 토큰만으로 자동 활성화할 수 없습니다.
3. `.github/workflows/pages.yml`은 `main`에 푸시할 때 소스 묶음 일치 확인, 구문 검사와 핵심 테스트를 실행한 후 정적 파일만 패키징하고 배포합니다. 배포 후에는 실제 공개 주소를 Chromium으로 열어 기록·계산·백업·모바일·오프라인 시나리오를 검증합니다. 브라우저 검사 도구는 CI 임시 폴더에만 설치합니다. 사이트 실행에는 추가 패키지가 필요하지 않습니다. 별도 유료 API나 배포용 비밀키는 사용하지 않습니다.
4. 최초 설정 전에 워크플로가 실행되어 실패했다면 **Actions → Validate and deploy website → Run workflow**에서 다시 실행합니다. 이후에는 `main` 푸시마다 자동 실행됩니다.
5. GitHub의 배포 작업이 완료되면 Pages 주소에서 확인합니다. 이 저장소의 기본 배포 주소는 `https://kawaiidoro.github.io/freeter/`입니다. 실제 게시 여부는 GitHub Pages에서 확인하세요.
6. 근무표 생성, 급여 계산, 기록 저장·새로고침, JSON 다운로드를 배포된 사이트에서 다시 확인합니다.

GitHub API 관리 권한이 제공되면 에이전트가 Pages를 활성화할 수 있습니다. Git 전송 권한과 Pages 설정 변경 권한은 별개입니다. `api.github.com` 및 `kawaiidoro.github.io` 접속이 환경 네트워크 정책에서 허용되어야 설정 변경과 공개 주소 검증을 진행할 수 있습니다.

모든 이미지·CSS·JavaScript·페이지·매니페스트 경로는 상대 경로입니다. `/freeter/` 같은 하위 경로를 지원합니다. `sitemap.xml`, `robots.txt`와 각 HTML의 canonical URL은 위 저장소 주소를 기준으로 작성했습니다. 계정·저장소·커스텀 도메인을 바꾸면 이 주소들도 함께 수정하세요.

각 기능은 독립된 HTML 주소와 고유한 제목·설명을 갖습니다. JavaScript 사용 시 페이지 이동은 History API로 처리하며, 직접 진입·새로고침·뒤로 가기도 지원합니다. 모든 탭 제목에 **Freeter**가 포함됩니다.

## 모바일 · PWA · 접근성

- 모바일 하단 내비게이션, 다크모드, 가로 스크롤 없는 근무표를 제공합니다. 기록표는 데이터 양에 따라 가로 스크롤을 지원합니다.
- 키보드 포커스 표시, 본문 건너뛰기, 폼 레이블, 대화상자, 상태 알림과 통계 데이터 표를 제공합니다.
- HTTPS 또는 로컬 개발 환경에서 서비스 워커를 등록합니다. 한 번 로드한 뒤에는 핵심 앱 파일을 캐시하여 오프라인 진입을 지원합니다. 개인 기록을 서비스 워커 캐시에 넣지 않습니다.
- Android Chrome 메뉴 또는 iOS Safari 공유 메뉴에서 홈 화면에 추가할 수 있습니다. SVG 아이콘·설치 표시 방식과 공유 지원은 브라우저에 따라 다릅니다.
- 화면 스타일·계산·기록은 브라우저 API와 함께 저장소에 포함된 메모 편집기를 사용합니다. Chrome 계열 자동 검증과 삼성 인터넷 사용자 에이전트·터치·API 제한 재현 검사를 포함합니다. Safari 및 Samsung Internet의 실제 기기는 별도 확인 대상입니다.
- `node scripts/build-site.mjs`는 런타임·스타일·서비스 워커 소스의 해시를 계산하고 9개 HTML의 버전 URL·`version.json`·`sw.js`를 함께 생성합니다. 생성된 `sw.js`를 직접 수정하지 말고 `scripts/sw-template.js`를 수정하세요.

## 검증

Node.js 22 이상에서 고정된 의존성을 설치한 뒤 핵심·동기화·PostgreSQL 보안 검사를 실행합니다. 권장 런타임은 Node.js 24입니다.

```sh
npm ci --ignore-scripts
npm test
node scripts/build-site.mjs --check
node scripts/build-vendor.mjs --check
node scripts/security-audit.mjs
# 운영 Supabase 공개 API 검사 (인터넷 필요, 사용자 기록 접근 없음)
npm run check:backend
```

선택적으로 Playwright와 Chromium이 준비된 환경에서는 실제 브라우저 검증을 실행합니다. 웹사이트 실행 자체에는 Playwright나 Node.js가 필요하지 않습니다.

```sh
# /workspace 전체를 정적으로 제공하여 하위 경로 로딩도 검증
python3 -m http.server 4173 --bind 0.0.0.0 --directory /workspace
# 다른 터미널에서 (Playwright가 사용 가능한 환경)
TEST_BASE_URL=http://127.0.0.1:4173/dangi-alba/ CHROMIUM_PATH=/usr/bin/chromium node tests/browser.mjs
TEST_BASE_URL=http://127.0.0.1:4173/dangi-alba/ CHROMIUM_PATH=/usr/bin/chromium node tests/features.mjs
TEST_BASE_URL=http://127.0.0.1:4173/dangi-alba/ CHROMIUM_PATH=/usr/bin/chromium node tests/brand.mjs
CHROMIUM_PATH=/usr/bin/chromium node tests/editor.mjs
CHROMIUM_PATH=/usr/bin/chromium node tests/update-recovery.mjs
CHROMIUM_PATH=/usr/bin/chromium node tests/startup.mjs
CHROMIUM_PATH=/usr/bin/chromium node tests/security-browser.mjs
CHROMIUM_PATH=/usr/bin/chromium node tests/account-browser.mjs
CHROMIUM_PATH=/usr/bin/chromium node tests/weather-browser.mjs
CHROMIUM_PATH=/usr/bin/chromium node tests/refinements-browser.mjs
# 인터넷 연결이 허용된 환경에서 공개 날씨 API와 사이트 CORS 검사
node scripts/weather-check.mjs
```

브라우저 테스트의 다운로드·스크린샷은 `/tmp/dangi-alba-tests`에 저장하며 저장소나 실제 사용자 기록을 건드리지 않는 별도 브라우저 컨텍스트를 사용합니다.

```text
version.json           현재 배포 릴리스 식별자
scripts/sw-template.js 서비스 워커 생성 원본
robots.txt             검색 로봇 안내
sitemap.xml            실제 HTML 페이지 목록
tests/                 계산·데이터 및 브라우저 회귀 검증
.github/workflows/     main 푸시 시 검사 및 Pages 자동 배포
```

방문자와 배포용 소스에는 `site.js`가 포함되어 있으므로 설치·빌드가 필요하지 않습니다. 개발 환경은 Node.js 22 이상에서 `npm ci --ignore-scripts`로 준비합니다. 개발 중 앱·계정·편집기·스타일·서비스 워커 템플릿을 수정했다면 `node scripts/build-site.mjs`를 실행하여 런타임과 버전 참조를 함께 갱신하세요. 라이브러리를 갱신하면 `node scripts/build-vendor.mjs`도 실행합니다. 포함된 Quill의 라이선스는 `vendor/QUILL-LICENSE.txt`에 있습니다.

## 광고 확장

사용 가이드 하단의 `.ad-space`는 향후 광고·서비스 공지 영역으로 준비했습니다. 입력창이나 계산 버튼 주변에는 배치하지 않았습니다. 실제 AdSense 코드는 포함하지 않습니다. 광고 도입 전 개인정보 안내, 적용 법령과 필요한 동의 절차를 갱신하세요.

- 공개 주소·canonical·공유 이미지·사이트맵·검색 로봇 안내를 `https://kawaiidoro.github.io/freeter/`로 통일합니다. 이전 `/dangi-alba/` 주소는 GitHub Pages에서 자동으로 이동하지 않습니다.
