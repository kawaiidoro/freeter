# 보안 점검과 변경 사항

점검일: 2026-10-17. 범위는 Freeter 프런트엔드, npm 의존성·배포 자동화, 계정 저장·인증 흐름과 제공한 Supabase SQL입니다. 사용자 개인 기록이나 실제 Google 계정은 검사에 사용하지 않습니다.

## 확인한 취약점과 수정

| 항목 | 확인·수정 내용 |
| --- | --- |
| Quill HTML 내보내기 XSS | `CVE-2025-15056` / [GHSA-v3m3-f69x-jf25](https://github.com/advisories/GHSA-v3m3-f69x-jf25). 공식 2.0.3에는 수정 릴리스가 없어 빌드 단계에서 `Editor.getHTML`의 DOM 직렬화를 제거하고 이스케이프한 일반 텍스트와 고정 `<br>`만 반환하도록 수정했습니다. 악성 태그·DOM 속성·이벤트를 넣은 실제 브라우저 회귀 검사를 실행합니다. Quill의 원본 npm 패키지에는 감사 경고가 남지만 배포되는 코드는 패치한 별도 빌드입니다. 버전을 낮춰 경고만 지우지 않습니다. |
| 다른 사용자의 근무 기록 접근 | RLS를 강제하고 읽기는 JWT의 본인 ID만 허용합니다. 익명 권한과 직접 쓰기 권한을 제거했습니다. 저장 RPC는 호출자의 `auth.uid()`만 사용하며 다른 사용자 ID를 매개변수로 받지 않습니다. 고정 빈 `search_path`와 SQL 매개변수를 사용합니다. |
| 계정 전환·늦은 응답 | 계정별 브라우저 저장 키와 응답 세대 검사를 추가했습니다. 계정이 바뀌면 열린 편집·삭제 확인을 닫고 이전 계정 응답을 적용하지 않습니다. 로그인 전 기록은 별도로 유지하며 자동 업로드하지 않습니다. 늦게 완료된 로그아웃은 새 계정이나 같은 계정의 새 로그인 사본을 지우지 않습니다. |
| OAuth 코드·세션 취급 | 공식 Supabase SDK 2.118.0의 PKCE를 사용하고 서버의 `getUser()`로 사용자를 확인합니다. 코드·토큰·오류는 URL에서 제거합니다. 로그인 전 공급자 상태를 확인해 설정 오류 시 현재 페이지와 기록을 유지합니다. Google 비밀번호·메일·Drive 권한을 받지 않습니다. |
| XSS 방어 | 9개 HTML에 CSP를 적용해 인라인 스크립트·eval·플러그인·base URL 변경을 차단하고 API 연결을 설정한 Supabase 프로젝트와 `api.open-meteo.com`·`air-quality-api.open-meteo.com`으로 제한합니다. 인증 SDK는 저장소 확인 후 지연 초기화해 저장소가 차단된 브라우저에서도 첫 화면을 유지합니다. 글자색·크기 등은 허용 목록의 Delta로 검증하고 이름·이메일·메모는 안전하게 출력합니다. `no-referrer`를 적용합니다. |
| 캐시·로그 | 서비스 워커는 공개 정적 파일만 캐시합니다. 인증 콜백·토큰 매개변수·Authorization 요청을 제외합니다. 세션·관리 토큰·DB 응답 원문은 로그나 공개 설정에 남기지 않습니다. |
| 데이터 유실·삭제 취소 | 서버 리비전 비교로 오래된 저장을 거부합니다. 독립된 기록은 3방향 병합하고 같은 항목 충돌은 두 자료를 백업한 뒤 선택합니다. 전체 삭제·전체 교체의 세대 변경으로 오래된 오프라인 기기가 삭제한 기록을 자동 복원하지 않게 합니다. 저장 원본 손상·용량 초과 시 자동 덮어쓰기를 멈춥니다. |
| 서버 저장 검증 | 저장 RPC의 성공 응답 후 본문·리비전·삭제 세대를 서버에서 다시 읽습니다. 확인이 끊기거나 본문이 다르면 초안을 유지하며 완료로 표시하지 않습니다. 서버 행 소실·리비전 후퇴도 로컬 기록을 빈 기록으로 바꾸지 않습니다. JSONB의 객체 속성 순서는 비교에서 무시하되 배열 순서는 보존해 서식 메모의 잘못된 충돌을 수정했습니다. |
| 연결 복구 | API 요청은 본문 수신까지 15초 제한과 취소 신호를 적용합니다. 최초 사용자 검증이 일시 실패한 경우 온라인 복귀·앱 재진입 시 세션을 재검증합니다. 계정 창에는 최근 서버 확인 시각을 표시합니다. |
| 날씨와 위치 | 창을 열 때만 공개 날씨 API를 호출하고 쿠키·인증 헤더·리퍼러를 전송하지 않습니다. 현재 위치는 별도 버튼·브라우저 권한을 거쳐 소수점 둘째 자리 좌표만 전송하며 기록·계정·오프라인 캐시에 위치를 남기지 않습니다. 외부 날씨 응답은 온도·단위·당일 날짜를 검증하고 문자열은 HTML로 삽입하지 않습니다. 권한 거부·오류·요청 취소를 처리합니다. |
| PNG 이미지 저장 | `html-to-image` 1.11.13(MIT)을 고정해 자체 번들로 제공합니다. 외부 렌더링 서버에 기록을 보내지 않으며, 복제본은 임시로 렌더링한 후 제거합니다. 저장 전 계정 변경 여부를 검사하고 긴 표를 캔버스 한도 내에서 나눕니다. |
| 공급망 | npm 버전·lockfile·생성된 브라우저 코드와 체크섬을 고정합니다. 설치 스크립트 실행을 끄고, 직접 사용하는 GitHub Actions는 검증한 커밋 SHA로 고정합니다. 주간·PR 보안 검사와 Dependabot 업데이트 설정을 추가했습니다. |

## 의존성 감사의 정확한 결과

`node scripts/security-audit.mjs`는 전체 `npm audit --json`을 실행합니다. 점검 당시 upstream 경고는 Quill 2.0.3의 위 항목 **낮음 1건**, 중간·높음·치명적 0건입니다. Quill은 배포 빌드에서 별도 수정했으며, 해당 공지 외의 새로운 경고는 심각도와 무관하게 CI를 실패시킵니다. 원본 npm 감사 경고가 0건이라고 보고하지 않습니다. 패치를 제거하거나 원본 배포 파일로 교체하면 안 됩니다. 새 공식 수정판이 나오면 패치와 예외를 재검토합니다.

공식 SDK·Quill과 전이 의존성은 고정한 lockfile에서 빌드하며 `node scripts/build-vendor.mjs --check`가 재현성을 확인합니다. 일반 텍스트 HTML 내보내기는 의도한 보안 변경입니다. 사이트 내부의 굵기·밑줄·크기·색·마커·읽기 보기와 JSON 서식 백업은 유지합니다.

## 검사와 실제 운영의 구분

- `tests/database.test.mjs`: 실제 PostgreSQL 엔진인 PGlite에서 마이그레이션을 실행합니다. 테스트용 Auth 역할·UID를 만들고 익명·다른 계정·직접 쓰기·오래된 리비전·잘못된 자료를 거부하는지 검사합니다.
- `tests/cloud.test.mjs`: 계정 격리, 미전송 기록, CAS 충돌·병합, 삭제 세대, 늦은 응답·저장 공간 오류·로그아웃을 검사합니다.
- `tests/security-browser.mjs`: 브라우저가 CSP를 실제로 강제하는지와 Quill 공격 입력·붙여넣기·콜백 캐시 제외를 검사합니다.
- `tests/weather-browser.mjs`: 실제 한글 IME 조합의 입력 안내 숨김과 공개 날씨 API 모사의 성공·오류·오프라인·위치 권한·좌표 축약·저장소 보존·취소·모바일 접근성을 검사합니다.
- `tests/account-browser.mjs`: 공식 Supabase SDK를 모사한 OAuth·REST API에 연결해 PKCE 왕복, 두 브라우저 계정 동기화, 서식 보존, 계정 전환·로그아웃·확인창 취소를 검사합니다. 실제 Google 인증이나 호스팅 DB 검사로 간주하지 않습니다.

운영 프로젝트에 `npm run check:backend`를 실행해 Google 공급자 활성화와 익명 테이블 읽기·저장 RPC의 HTTP 401 / `42501` 차단을 확인했습니다. 이 검사는 로그인 세션이나 관리자 키 없이 실행하며, 조회는 `revision` 열의 0개 행으로 제한하고 저장 검사는 NOT NULL 제약을 만족할 수 없는 NULL을 전송합니다. 개인 기록 본문은 읽거나 로그에 남기지 않습니다. Pages 배포 후에도 같은 검사를 실행합니다.

사용자는 실제 PC·휴대폰에서 같은 Google 계정의 변경이 양쪽에 반영된다고 확인했습니다. 에이전트가 사용자의 로그인 세션으로 저장한 것은 아니며, 운영 DB의 서로 다른 두 Google 계정 간 접근 격리를 직접 검사한 것으로 대신 보고하지 않습니다. RLS의 교차 계정 검사는 격리된 실제 PostgreSQL 엔진에서 수행했습니다. 관리자 설정 변경에는 별도의 관리 권한이 필요하며 [설정 지침](SUPABASE.md)을 참고하세요.

## 운영상 남는 경계

GitHub Pages에서는 애플리케이션이 임의의 HTTP 응답 헤더나 HttpOnly 인증 쿠키를 설정할 수 없습니다. 브라우저 SDK 세션은 localStorage를 사용하고 DB는 종단간 암호화를 제공하지 않습니다. 동일한 `kawaiidoro.github.io`의 다른 경로도 같은 브라우저 저장 영역을 공유합니다. 별도 앱들과 저장·인증 출처를 격리해야 한다면 전용 도메인이나 서버 호스팅이 필요합니다. CSP의 스타일 인라인 허용은 메모 서식·그래프에 필요하며 스크립트 인라인 실행은 허용하지 않습니다. 운영 관리자의 권한·Supabase 백업·Google 앱 게시 정책·실기기 검사는 코드 자동 검사와 별도입니다.
